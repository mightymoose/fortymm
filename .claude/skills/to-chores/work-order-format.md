# Work-order format

The single source of truth for the `.claude/work-order.md` structure. `/to-chores`
writes it; `/do-chores` reads it. The **checkboxes are the run state** — a ticked
box means that chore is done and verified; `/do-chores` resumes from them.

## Structure

```markdown
# Work order: <plan title>

Source: <path/URL to the plan, PRD, or issue — or "conversation">
Generated by /to-chores. Drive with /do-chores. Checkboxes are the run state.

## Slice 1: <demoable outcome — a full sentence you could verify by hand>

- [ ] 1a `[api]` Add rating to the profile BFF response + schema
  - **Scope:** the profile BFF endpoint only; no rating *computation* changes.
  - **Depends on:** —
  - **Read first:** docs/adr/0007-rating-on-profile.md
  - **Verify:** `pytest tests/test_profile.py`
- [ ] 1b `[main]` Regen OpenAPI types (schema.d.ts + Types.swift)
  - **Scope:** generated types only; no hand edits.
  - **Depends on:** 1a
  - **Verify:** `mise run regen-api-types && mise run regen-ios-api-types` — no drift
- [ ] 1c `[web-client]` Render the rating on the profile page
  - **Scope:** profile page + its e2e page.route stubs.
  - **Depends on:** 1b
  - **Read first:** docs/adr/0007-rating-on-profile.md
  - **Verify:** `npm run test:run && npm run test:e2e`
- [ ] 1d `[ios]` Show the rating on the profile screen
  - **Scope:** profile screen only.
  - **Depends on:** 1b
  - **Verify:** `xcodebuild build ... CODE_SIGNING_ALLOWED=NO`

## Slice 2: <demoable outcome>

- [ ] 2a `[web-client]` ...
```

## Field rules

- **Checkbox + ID** — `- [ ] <slice-number><letter>`. IDs are stable and unique;
  `depends-on` references them.
- **Agent tag** — one of the `name`s discovered from `.claude/agents/` (`[api]`,
  `[web-client]`, `[ios]`, `[infra]`, `[e2e]`), or `[main]` for a chore the driver
  does inline (regen, integration, glue). Exactly one tag per chore.
- **What to build** (the text after the tag) — behavior + surface, one line, no
  "and". **No hard file paths** — name the surface, not the file.
- **Scope** — one line on what the chore does *not* touch, to keep it single-tree
  and atomic.
- **Depends on** — comma-separated chore IDs that must be ticked first, or `—`.
- **Read first** (optional) — path(s) to the ADR / `CONTEXT.md` section carrying
  the decision this chore needs. Omit when there's nothing to read.
- **Verify** — the concrete command the implementing agent runs to prove the chore
  is done. Must be checkable, not a vibe.

## Blocked chores

When `/do-chores` stops a slice on failure, it marks the failed chore so a resume
can see it — append `⚠ BLOCKED: <reason>` to the chore line and leave the box
unchecked:

```markdown
- [ ] 3b `[api]` ... ⚠ BLOCKED: pytest failing on the FK constraint, see run notes
```
