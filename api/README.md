# api

fortymm's HTTP API: FastAPI on Python 3.15, with PostgreSQL 18 (the `api-db` service). Run everything through `./bin/mise run api:<task>`; `CLAUDE.md` lists the tasks.

- `src/api/app.py` builds the app. Settings come from the environment at startup (`src/api/settings.py`; `DATABASE_URL`).
- `GET /health` runs `SELECT 1` and answers 200 `{"status": "ok", "database": "ok"}`, or 503 `{"status": "unavailable", "database": "unavailable"}` when the database doesn't answer within 2 seconds. The cause is logged, never returned.
- `openapi.json` is the API's contract, generated by `api:openapi`. CI fails when it is out of date.
- `Dockerfile` is the production image. The dev image is `dev/api/`.

## Tests

| What you're proving | Where | How |
| --- | --- | --- |
| A rule in a pure function | `tests/unit/test_<module>.py` | Call it directly. No database, no app. |
| What a route does | `tests/http/test_<route>.py` | `api_client(database_url)` from `tests/support/api_client.py` runs the whole app in process against the real `api_test` database. Assert on the status code and the body. |
| A route's behavior when the database fails | Same | `tests/support/database_faults.py` has stand-ins for a database that is gone, silent, or never answers a query. |
| A response matches the OpenAPI document | Same | `assert_matches_documented_response` from `tests/support/openapi.py`. |
| The shipped image is wired up | `../e2e/api/tests/` | One test per journey, happy path only, against `api-release`. |

Tests are async (`pytestmark = pytest.mark.anyio`). A test that writes rows creates what it needs and is safe to run twice; the database is not reset between runs.
