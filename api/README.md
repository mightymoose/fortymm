# api

fortymm's HTTP API: FastAPI on Python 3.15, with PostgreSQL 18 (the `api-db` service). Run everything through `./bin/mise run api:<task>`; `CLAUDE.md` lists the tasks.

## Layout

| Where | What goes there |
| --- | --- |
| `src/api/services/<concern>.py` | A service class that holds one piece of logic, plus the result models it returns. It returns results for expected outcomes instead of raising, and knows nothing about HTTP: no status codes, no FastAPI types, no `JSONResponse`. |
| `src/api/routes/<resource>.py` | A route gets its service from `api.dependencies`, calls it, and turns each result into a status code and body. No logic of its own. |
| `src/api/dependencies.py` | FastAPI dependencies that build services from settings (and, later, the connection pool). |
| `src/api/app.py` | `create_app()`: reads settings from the environment at startup (`src/api/settings.py`; `DATABASE_URL`) and includes the routers. |
| `openapi.json` | The API's contract, generated by `api:openapi`. CI fails when it is out of date. A result model used as a response body is in it under its class name. Use comments, not docstrings, on those models unless you mean to change the document. |
| `Dockerfile` | The production image. The dev image is `dev/api/`. |

The example is the health check. `HealthCheck.run()` (`services/health_check.py`) runs `SELECT 1` within 2 seconds, logs the cause of a failure, and returns `HealthOk` or `HealthUnavailable`. `GET /health` (`routes/health.py`) answers 200 or 503 with that result as the body.

## Tests

| What you're proving | Where | How |
| --- | --- | --- |
| A rule in a pure function | `tests/unit/test_<module>.py` | Call it directly. No database, no app. |
| Every case of a service's logic | `tests/services/test_<service>.py` | Call its public methods and assert on the result it returns. The database is the real `api_test` (`database_url` fixture). For a database that is gone, silent or never answers, use the stand-ins in `tests/support/database_faults.py`. |
| A route is hooked up and translates each result | `tests/http/test_<resource>.py` | One case per outcome, through `api_client(database_url)` (`tests/support/api_client.py`): the whole app, the real service, the real database, nothing faked. Assert the status code and the body. Don't repeat the service's cases, and don't assert that the route called the service. |
| A response matches the OpenAPI document | Same | `assert_matches_documented_response` (`tests/support/openapi.py`), once per documented status. |
| The shipped image is wired up | `../e2e/api/tests/` | One test per journey, happy path only, against `api-release`. |

Tests are async (`pytestmark = pytest.mark.anyio`). A test that writes rows creates what it needs and is safe to run twice; the database is not reset between runs.
